# P7.06-UI3 — Proof harness historical-controller review

Status: `Repository proof-harness remediation under review; selected-Mac execution pending`  
Task classification: `platform`  
Authority checked: Constitution `1.2.0` Ratified; RFC-0001, RFC-0003, RFC-0005, RFC-0006 Accepted; no applicable Accepted ADR.

This is a bounded operational proof-harness correction discovered after the UI3 functional review reached its maximum 7/7 iterations. It does not reopen or extend that functional review, does not change UI3 security/authority semantics and is not UI3 closure or roadmap advancement.

## Trigger

The selected-Mac current-pointer forensics established that the latest attempted P7.06 update failed before a new deployment transaction because `current` and the live P7.02 runtime release were inconsistent. During preparation of the bounded consistency recovery path, the existing selected-Mac UI3 proof runner was re-read against the already-merged PR #64 historical-release reconciliation design.

A proof-harness defect was found: after the proof performs governed rollback to an exact historical source release that contains UI3, the core runner calls the **historical source copy** of `p7_06_ui3_macos_operator.sh` for status and the final governed update. That replays historical lifecycle-controller behavior during the very proof intended to validate the hardened current controller. In the currently relevant rollback source (`6d4d07aead603841ecce3c469dd46f5e0d58ccd5`), this can reintroduce pre-hardening lifecycle behavior and produce a false operational failure.

The actual service, Python, module, config and launchd plist must remain exact-release pinned to the release represented by `current`; the defect is only which lifecycle controller orchestrates those exact-release operations.

## Remediation

`reference/python/p7_06_ui3_selected_mac_proof_runner.py` becomes the supported proof entry point. It:

1. requires itself to execute from the exact active target release;
2. resolves the exact target release's hardened `p7_06_ui3_macos_operator.sh`;
3. delegates all proof semantics to the existing core `p7_06_ui3_selected_mac_proof.py`;
4. intercepts only shell invocations whose executable script basename is `p7_06_ui3_macos_operator.sh`;
5. rewrites those invocations to the exact target hardened controller while preserving the requested lifecycle operation and arguments;
6. leaves direct P7.06 deploy calls unchanged, including the pre-UI3-source fallback path;
7. records in the normal UI3 attestation that the hardened controller runner was verified and historical UI3 controller replay did not occur.

The hardened controller itself remains dynamic over `current`: after rollback it verifies and operates the historical exact-release Python/module/config/plist, and when it performs the final governed update it delegates to the current historical P7.06 deploy adapter before reconciling the resulting release. This preserves exact-release semantics without replaying historical controller defects.

## Review/revise

### Iteration 1 — exact-release integrity

Concern: using the target controller after rollback must not make the historical service execute target-release code.

Resolution: the controller's existing `current_release()`, `release_python()`, `release_script()`, `config_port()` and plist verification resolve service code from the actual current release. The wrapper only substitutes the controller shell path; it does not substitute service Python/module paths.

Result: `PASS`.

### Iteration 2 — scope of interception

Concern: a broad command rewrite could accidentally replace the historical P7.06 deploy adapter, changing governed deployment semantics.

Resolution: interception is restricted to `sh <...>/p7_06_ui3_macos_operator.sh ...`. Calls to `p7_06_macos_deploy.sh` are explicitly not rewritten and tests cover the distinction.

Result: `PASS`.

### Iteration 3 — evidence and governance

Concern: the correction must remain visible in proof evidence and must not introduce P7.04 provisioning, authority or UI4 interaction.

Resolution: the wrapper augments the existing attestation before it is written with:

- `hardened_controller_runner_verified = true`;
- `historical_ui3_controller_replayed = false`;
- exact hardened-controller release SHA.

The underlying core proof remains responsible for P7.03/P7.04 integrity, private HTTP/session checks, rollback/re-update, no Organizational Authority/consequential approval and no real UI4 interaction.

Result: `PASS`.

No material repository-scope proof-harness objection remains after iteration 3. Selected-Mac execution remains required.
